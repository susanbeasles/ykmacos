# Initial signer enrollment

`yk signers enroll --certificate SHA256 --token TOKEN --team TEAM --receipt PATH --policy NEW_PATH --json` verifies the retained possession receipt, revalidates the exact connected identity, and makes one signing call for a closed initial policy. macOS/token policy controls PIN and touch. No credential is received or stored by the application. Existing output records are never replaced, and signature failures never retry.

The policy binds the selected certificate digest, token ID, Team ID, exact possession receipt file digest and a new 256-bit nonce. Its domain is `ykmacos.signer-enrollment.v1`, its revision is 1, hardware origin is `unverifiable`, backup coverage is `unknown`, and its allowed operation list is empty. It is initial signer enrollment evidence; it cannot authorize application signing, data encryption, secret access, device changes, recovery changes or remote operations. The existing key is neither regenerated nor imported.

`yk signers verify` takes the same explicit certificate/token/team pins, receipt and policy paths. Pins must come from an independently selected identity, not from the untrusted policy file. The verifier checks exact closed policy bytes, its signature, the receipt digest, the receipt signature and current offline certificate checks. Policy and possession domains cannot substitute for one another. Unknown policy/envelope fields, altered revisions, recovery claims and added operations reject. The token is not needed for verification.

The returned `policyDigest` hashes the exact sealed record. Retain the pin and digest independently. This release does not establish a trusted current-policy revision anchor or rollback resistance. It never interprets a retained receipt as current possession or a signed token-ID claim as hardware attestation. Fresh revocation remains unknown offline. A valid policy may be copied; initial verification grants no operational authority. Full policy lifecycle and operation enforcement must establish current revision, recovery coverage and immutable operation plans before enabling protected operations.

Enrollment holds the destination directory descriptor from before authentication until publication, checks its identity again, then writes through the held descriptor. It refuses symlink components and existing output names. A concurrent destination creation makes commit fail without overwriting it. Directory movement after the final check may make the record available at the original directory's new location; the descriptor still determines the committed resource. Native descriptor/durability behavior must be validated on macOS. Same-user malicious processes or hostile root/kernel are outside the protection supplied by local files alone.

Commit failures are uncertain, not invitations to sign again: preserve any record and run the read-only verifier first. Read-only verification does not repair or overwrite records. Failed public evidence does not justify regenerating keys. Initial enrollment does not change authentication fallbacks, PINs, certificates or backup hardware.

Unit tests check the closed policy boundary and foreign selections. Native signing and file behavior require Mac validation; destructive credential and retry-counter tests remain restricted to disposable hardware.
